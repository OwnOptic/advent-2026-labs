Claude reads the transcript and writes a functional and technical blueprint, with two diagrams. Every requirement cites the moment of the workshop it came from, and the two questions the team left open are flagged, not guessed.

1Prepare SharePoint

⏱️ About 5 minutes

  1. Download the documents zip and the sharepoint-setup.ps1 script into the same folder.
  2. Once, if the module is missing: Install-Module Microsoft.Graph.Authentication -Scope CurrentUser.
  3. Run the script in PowerShell 7, from that folder, with the SharePoint host of your test tenant. A sign-in window opens: sign in with your test account and accept the permissions.
Result: the Contoso - Human Resources site (/sites/contoso-hr), its New starters list with two past new starters, the 5 documents in the Documents library, and remote-work-policy-2021.pdf in the Archives folder. That old policy is the trap of step 5: keep it. Open the list to check.
You can run the script again safely: it reuses what already exists. Two reasons to run it again: the site was not ready yet (creating it takes one to three minutes), or the two new starters have no manager because your account was not known to the site yet (open the site once, then run it again). Already have a site? Add -SiteUrl https://your-tenant.sharepoint.com/sites/your-site.

The columns the script creates, and their internal name, the one the workflow uses:

Displayed nameInternal nameType
Full nameTitleSingle line of text
EmailEmailSingle line of text
Job titleJobTitleSingle line of text
Start dateStartDateDate only
ManagerManagerPerson
BuddyBuddyPerson
Equipment handed overEquipmentHandedOverChoice: No, Yes (No by default)
By hand instead of the script? Create each column first with its internal name, then rename it to its displayed name: SharePoint keeps the first name as the internal name. A column created directly as "Equipment handed over" would get an unreadable internal name and the workflow would fail.

Creating them now avoids any consent window later. Claude creates the three Dataverse connection references that point to them by itself: that is how a Copilot Studio workflow uses a connection.

3From the workshop to the blueprint

⏱️ About 10 minutes, a few of them with Claude working on its own

  1. Unzip the starter folder to a new folder, for example C:\lab-onboarding. It contains workshop-transcript.txt and templates\blueprint-template.html.
  2. Put your CLAUDE.md from step 2 at the root of that folder. Claude Code reads it at the start of every session.
  3. Open a terminal and sign in: az login --tenant YOUR_TENANT_ID.
  4. Open a new session of Claude Code on that folder: in the Claude desktop app, Code tab, choose the folder; or in a terminal, cd C:\lab-onboarding then claude.
  5. Paste this prompt and send it:
What should happen: Claude reads the 38 minutes of transcript, copies the template to blueprint\onboarding-blueprint.html, fills every zone, draws the journey and the architecture, and opens the page. Scroll it: the pain points, the requirements with their timestamps, the two diagrams, and two open questions in their own blocks. The team did not decide who gets the equipment reminder, nor whether the buddy needs a message: Claude flags them instead of guessing.
Why a blueprint first? It is the contract between the business and the build. Anyone in the workshop can check any line against what was actually said, and the build in step 4 only follows the blueprint.

4Decide, then build the workflow

⏱️ About 15 minutes

  1. In the same session, answer the two open questions and ask for the workflow:
What should happen: Claude turns the two open blocks into decided blocks, shows the workflow steps, creates the connection references, writes flow\create-workflow.ps1 (the definition and the editor graph), saves the workflow in Dataverse, turns it on and gives you the link. It opens in the new editor of Copilot Studio, Workflows page. The editor badge may say "Draft" even though the workflow is on.
Why Dataverse? A Copilot Studio workflow is a row of the Dataverse workflows table. It holds two views of the same workflow: the definition that runs and the graph the editor draws. Without the graph, the workflow runs but the editor cannot show it; CLAUDE.md gives Claude the exact rules.

Test

  1. Add a row to the list: Camille Martin, the email of a test account, a start date in the past (the 3-day wait is then already over), Equipment handed over: No.
  2. The trigger polls every minute. Tell Claude the row is added: it follows the run and summarises each action.
Result: the welcome email, the Teams message to the manager (sent by the Flow bot), the "Welcome coffee" invitation, then the equipment reminder. In Copilot Studio, the workflow's Activity tab shows each step in green: 7 of 7.
If Claude hesitates or wants to search the web: remind it that everything is in CLAUDE.md. If a session read an older version of the file, open a new one: a session sticks to what it read.

Did you know? A workflow run lasts at most 30 days. For a real onboarding, split it in two: the immediate welcome, and a daily reminder.

5The agent, on the Microsoft Copilot harness

⏱️ About 10 minutes

  1. Still in the same session, ask for the agent:
What should happen: Claude writes agent\instructions.txt and agent\create-agent.ps1, creates the Contoso Onboarding Assistant in Dataverse, adds the Human Resources site as its only knowledge source, turns web search off, publishes it and gives you the link. About 15 seconds of publishing.
  1. Open the link. In the Preview pane, ask:

🕵️ The trap: your guess

The site holds the 2026 remote work policy (two days) and, in the Archives folder, the 2021 one (one day). Before you read the agent's answer: which source will it cite?

Only the 2026 policy. Two days per week, with the manager's approval, and only the 2026 policy in the sources. That is thanks to one line of its instructions: "Ignore documents in the Archives folder". Without that line, the archive shows up in the sources even when the answer is right: a dead document stays a source as long as it sits on the site. In production, the real fix is to move the archive off the site.

Evaluate

  1. Evaluate tab: name "Contoso onboarding", Import, choose the Conversations type before dropping test-set-onboarding.csv (comma-separated values), then run it.
Expected result: about 90 percent in about 3 minutes. The question that often fails is the salary one: the "General quality" method can count a polite refusal as a non-answer. Read the answer, not only the score.

Publish

  1. Channels, Teams and Microsoft 365, "Microsoft Copilot and Microsoft Teams" (this choice cannot change after publishing), Add channel, then Publish.

6Clean up

⏱️ 5 minutes. The Microsoft Copilot harness uses Copilot credits for every test and evaluation.

  1. Copilot Studio, Workflows: turn off, then delete the "New starter onboarding" workflow.
  2. Copilot Studio: remove the agent from Teams, then delete it.
  3. SharePoint: delete the test rows, or the whole site if you do not keep it.

Before you publish an agent: 5 checks

Clean sources: one version of each policy, archives excluded.
Connections created in advance, with the right account.
An evaluation set of at least 10 questions, including out-of-scope ones.
Human approval wherever a mistake is expensive.
Credit consumption measured before opening it to everyone.
